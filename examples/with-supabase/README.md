# Fresh + Supabase password authentication

This example starts from the pinned official Fresh 2.3.3 Tailwind fixture and is
generated by this repository's `@fresh-supabase/cli` implementation. It uses
server-rendered Preact forms, POST + 303 redirects, request-scoped Supabase
clients, path-scoped CSRF, upstream-aligned global auth middleware, and no
runtime CLI dependency. Its 17 generated source files map one-to-one to Supabase
UI's upstream `password-based-auth-nextjs` block.

The root middleware commits Supabase's pending cookie and cache-header changes,
and the protected route reuses its verified claims without a second identity
request. Logout uses Supabase's `local` scope. Password length and complexity
are enforced by the connected Supabase project's policy.

## Configure

Copy `.env.example` to a local environment file and set:

- `FRESH_PUBLIC_SUPABASE_URL`;
- `FRESH_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.

Configure Supabase's confirmation email template to send `token_hash` and `type`
to `/auth/confirm`, following the Supabase SSR guide.

## Run

```bash
deno install --frozen
deno task --env-file dev
```

The login page is at `/auth/login`; the protected page is at `/protected`.
Anonymous application and API requests outside `/auth*` and `/login*` are
redirected globally to the login page, matching the upstream block.

## Verify

```bash
deno task check
deno task --env-file build
```

The repository's integration suite additionally checks the committed structure,
a mocked Supabase password-auth flow, and a Deno Deploy-mode build.
