# v0.2 real Supabase validation

- Date: 2026-08-07
- Application: official Fresh 2.3.3 Tailwind scaffold
- Installer: local `@fresh-supabase/cli@0.2.0` source
- Backend: local Supabase CLI 2.111.0 with GoTrue, Postgres, and Mailpit
- Result: pass

This release check complements the deterministic mocked integration suite. It
uses a real local Supabase stack and actual confirmation and recovery messages;
it does not replace future containerized CI coverage.

## Configuration under test

- Email confirmation was enabled.
- The project password minimum was six characters.
- Confirmation and recovery templates linked to the generated `/auth/confirm`
  endpoint with `token_hash`, `type`, and `next` parameters.
- The Fresh application was built for production and served from
  `_fresh/server.js`.
- Supabase credentials were passed only to the validation process. No key, test
  address, password, or token is recorded here or written to a project `.env`
  file.

## Finding incorporated into v0.2

Supabase CLI ignores `supabase/.temp` in Git, but Deno's unscoped type checker
can still discover TypeScript generated there. The `client` block now adds a
comment-preserving, idempotent `config.exclude.ensure` operation for
`supabase/.temp/**`. This keeps application checks focused on project source
without editing or relying on Supabase's transient runtime files.
