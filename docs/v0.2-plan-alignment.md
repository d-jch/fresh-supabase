# v0.2 plan alignment

This matrix records which ideas from the standalone-installer plan are part of
`@fresh-supabase/cli@0.2`, which were adapted to the existing CLI, and which
remain intentionally outside this increment.

## Adopted

| Design point                | v0.2 evidence                                                                                                                                                                                                                   |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fresh root alias            | `fresh-root-alias` requires the exact `"@/": "./"` mapping; generated project-local imports use `@/`.                                                                                                                           |
| Active file routing         | `fresh-file-routes` verifies that one imported Fresh `App` instance registers both `staticFiles()` and `.fsRoutes()`; unrelated calls and misleading import aliases fail closed.                                                |
| Default route directory     | `fresh-default-routes` accepts the omitted/default `routes` value and rejects custom, computed-custom, duplicate, spread, or otherwise unverifiable `routeDir` configuration.                                                   |
| Fresh define helper         | `fresh-define-helper` requires the actual exported name `define`; `export { define as other }` does not satisfy it. Routes use `define.handlers`, `define.page`, and `define.middleware`.                                       |
| Environment contract        | `.env` must be explicitly ignored; browser code uses literal `Deno.env.get("FRESH_PUBLIC_...")` calls; post-install guidance distinguishes local task loading from build/deployment configuration.                              |
| Fresh-native auth UI        | Auth uses server-rendered native forms, `page()` error responses, 303 redirects, `Head`, and zero islands.                                                                                                                      |
| App configuration           | Links, form actions, redirects, CSRF scope, and callback URLs honor `ctx.config.basePath`.                                                                                                                                      |
| Middleware behavior         | The password block owns an ordered root middleware array. Static assets bypass it; anonymous non-`/auth*` and non-`/login*` requests redirect globally like upstream. Immutable responses and 101 upgrades remain safe.         |
| Verified claims reuse       | Root middleware stores the result of `getClaims()` in request state; the protected route consumes those claims instead of adding a `getUser()` network request.                                                                 |
| Server cookie contract      | Standalone `client` installs expose pending cookie/cache-header state explicitly. Routes must commit it themselves; password auth commits it centrally in root middleware.                                                      |
| Supabase CLI temp isolation | `client` idempotently adds `supabase/.temp/**` to Deno's `exclude` array so local Supabase runtime output cannot pollute project-wide format, lint, or type checks.                                                             |
| Official testing seam       | Integration tests exercise `new App().use(...).get/post(...).handler()` directly with `Request` values. The e2e suite also checks a production Vite build and `_fresh/server.js` auth smoke flow.                               |
| Real-stack validation       | A local GoTrue/Postgres/Mailpit run validates signup confirmation, claims-backed protection, independent-session local sign-out, recovery, password update, and old-password rejection; see `v0.2-real-supabase-validation.md`. |
| Upstream inventory          | The resolved auth dependency closure maps exactly the current 17 Supabase UI source files to 17 Fresh targets and records the four upstream registry dependencies.                                                              |
| Safe upgrades               | Managed files upgrade only when their current hash still equals the previous manifest hash. Downgrades conflict at block level, including missing targets and configuration-only blocks.                                        |
| Dependency compatibility    | A compatible same-source host dependency is preserved; lower, broader, differently sourced, or unparseable mappings conflict.                                                                                                   |
| Cross-platform release gate | CI runs format, type/embedding checks, lint, package dry-run, and the full suite on Windows and Ubuntu.                                                                                                                         |

## Adapted to the existing project

| Plan idea                     | v0.2 decision                                                                                                                                                                                           |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Separate installer package    | Installation stays in `@fresh-supabase/cli add`; there is no `@fresh-supabase/install` package or duplicate state protocol.                                                                             |
| Remote registry pinned by SHA | The declarative registry is logically separate but embedded into the published CLI snapshot for now. This gives one tested artifact and no second runtime fetch.                                        |
| `ui-base` dependency          | The existing daisyUI block remains the renderer for this increment. Replacing the renderer is independent of the auth and installer changes.                                                            |
| `@std/http` cookie bridge     | The local adapter remains because it preserves the complete Supabase SSR cookie options, custom encoding, chunking, and cache-header behavior; those contracts are tested directly.                     |
| Extra Fresh auth files        | Upstream alignment is defined by the resolved 17-target closure. Sign-out is handled by the upstream-mapped logout component and protected route instead of adding targets not present upstream.        |
| Global auth policy            | Upstream's broad anonymous redirect is preserved, including for application pages and webhooks. It is activated only by `password-based-auth`; installing `client` alone does not wire root middleware. |
| Sign-out scope                | The generated POST action deliberately uses Supabase's `local` scope, so signing out does not terminate the user's sessions on other devices.                                                           |
| Password policy               | Generated forms require non-empty matching values but leave length and complexity enforcement to the Supabase project's configured policy.                                                              |

## Deferred with explicit boundaries

| Deferred item                                              | Reason / trigger                                                                                                                                                      |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Existing middleware syntax merge                           | Current managed-file creation conflicts safely. A generic merge operation needs syntax-aware parsing and fixtures for single, array, alias, and unrecognized exports. |
| Automatic `deno install` and lockfile rollback             | This expands the transaction boundary and subprocess permissions; it should be a separate test-backed increment.                                                      |
| Remote registries, SHA channels, and source override flags | Add when block release cadence justifies a remote protocol and its supply-chain controls.                                                                             |
| `minFresh`, `minDeno`, and destructive force flags         | Fresh 2 major and observable capabilities are checked now. Version floors and override semantics need their own compatibility contract.                               |
| Custom `serverEntry`, `routeDir`, and target roots         | v0.2 intentionally supports the official initializer shape. Custom path mapping needs a complete target-rewrite model rather than partial inference.                  |
| `islandsDir` enforcement and browser-client test harness   | The current auth block has zero islands. Add both when the first island-based block is introduced.                                                                    |
| Automated real-Supabase email smoke in CI                  | A real local-stack release validation is complete, but containerized CI automation and its lifecycle/caching policy remain a separate increment.                      |

## Rejected for v0.2

- A second `@fresh-supabase/install` package.
- Extra email-template files in the installed project when upstream treats them
  as Dashboard-managed configuration.
- `--unstyled`, because the current auth UI has an explicit renderer dependency
  and silently omitting it would generate a broken project.
- Arbitrary block-provided scripts or lifecycle hooks.
